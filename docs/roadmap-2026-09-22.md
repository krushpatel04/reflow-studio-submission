## Decision and evidence boundary

Keep the deterministic engine and viewer small, offline, and explicit about failures. Improve measured correctness, responsiveness and independent quality before adding models or campaign features. No finite test suite proves zero errors or coverage of every possible input: define a supported envelope, test its boundaries, and return actionable failures outside it. Removing resource safeguards would undermine offline reliability.

## Adversarial findings and assigned work

### Engine correctness

- **#25, JD — UTF-8 stream corruption:** `scripts/reflow-cli.ts:58–65` decodes each chunk independently. An isolated forced-boundary probe turns `Café` into JSON-valid `Caf��`; a full OS-scheduled CLI reproduction was not run. Test exact strings at every byte boundary and preserve raw-byte limits.
- **#26, JD — invalid successful output:** actual reflow probe with a 1×1 canvas and finite decoration width `1e308`, target 8000×8000, yields Infinity. Diagnostics detect invalid design, but selection still returns it and JSON emits null (`src/engine.ts:17,189–190`, `scripts/reflow-worker.ts:19–28`). Gate structural validity before success; keep valid designs with unresolved layout findings distinct.
- **#27, JD with Junho — invalid measurement fails open:** injected NaN width/ascent/descent produces zero errors/findings in an identity reflow (`src/typography.ts:27–31`, `src/evaluate.ts:98–99`). This proves a boundary defect, not that bundled fonts currently trigger it. Define valid measurement semantics and fail visibly with positive font/empty-text controls.

### Viewer execution and delivery

- **#28, Junho — request lifecycle:** `src/main.ts:53–55,79–98,111–120` recomputes targets synchronously, including presentation toggles. Mutation before recomputation can leave new source with old results on a later-target exception. These code paths are verified; normal-fixture stall timing was not measured. Add bounded result reuse, cancellable work, revision-safe export and explicit retry/revert; this is transient safety, not #14 persistence.
- **#29, Junho — actual downloaded SVG:** `src/main.ts:99–103` downloads preview DOM with font-family references and optional diagnostic overlays; only benchmark export separately embeds fonts. Code-observed risk, not a visually reproduced download failure. Test the actual download in a clean offline context and export artwork independently of overlays.
- **#30, Junho — production qualification:** test clean production startup without external networking, whole select/edit/compare/export flow, missing resources, repeated-use memory and artifact cost. The review's local dist observation (~1.58MB uncompressed) is not a fresh release baseline. Record a reproducible baseline before setting a regression gate.

## Lightweight performance and failure policy

- Keep corpus downloads, annotation, training and archived reports outside production engine/viewer artifacts. Add a dependency only with measured incremental size, startup, resident memory and runtime cost. Native fonts/assets remain local; no hidden external API or runtime download.
- #8 retains full cold startup/load/parse/resource setup/layout/render/export and process/container memory accounting. Measure representative and worst cases separately on named hardware; report sample counts and distributions before claiming p95/p99. A single stress timing is not a latency guarantee.
- Existing provisional input-size, element/text, canvas, deadline, output and container-memory bounds stay in force pending authoritative #4 limits. Test at, below and above each boundary; bound total work, retries/cache and candidate exploration. A worker deadline does not bound parent file-system delay or prove successful fallback. Preserve source on failure; never certify a least-bad invalid result.
- Proposed viewer interaction targets for qualification: visible feedback within 100ms, cancellation acknowledgement within 250ms, and no avoidable main-thread task over 50ms in the declared supported workload. These are internal starting targets to measure, not verified performance or Adobe requirements. #30 records final hardware-specific tolerances, startup/artifact/memory budgets and the justified changes if these targets prove inappropriate.
- Document accepted output with warnings separately from invalid output, unsupported input, timeout, resource failure and unavailable assets. Export/preview must refer to the same revision. No silent content loss, automatic source mutation or hidden failure row.
