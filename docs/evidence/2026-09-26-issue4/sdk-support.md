# Adobe Express native capability matrix

Official documentation retrieved September 26, 2026. **Every host-test cell is NOT TESTED**: [access stopped at sign-in](host-check.md). “Documented” does not mean integrated, accepted for competition, or available in the eventual account. No numeric host SDK/build version was observed; the UI SDK uses Adobe's hosted `sdk.js`, document modules are host-provided. Record actual host/version/configuration in the next run.

Status wording: **documented/unflagged** means the current cited member is not labeled experimental; it is not an independent stability guarantee. **Experimental** means the cited reference/changelog explicitly flags it. SDK API availability is separate from the provisional competition schema.

## Documentation traps found during audit

- Adobe still serves an older uppercase `/classes/Editor` reference with `queueAsyncEdit`; current navigation points to lowercase `/classes/editor` and `express-editor` with the active-content API. Use the current reference and host types, not the older cached page as the integration contract.
- The Add-on Mode page's illustrative snippet uses `app.documentSandbox.dispatch`, `text.create` and `insertNode`, while the current Architecture reference documents `runtime.apiProxy`/`exposeApi`, `editor.createText`, and `children.append`. This audit does not establish those illustrative calls are available. Prefer the current documented proxy pattern and verify against actual Playground types before writing a probe.
- Local Skia/SVG output, the official offline `cr-renderer` path and Adobe Express's native canvas are **three separate rendering environments**. Record each independently.

No API code was added. A runbook is safer than shipping an unexecuted example as a proven probe, especially after the qualification viewer requirement changed.
