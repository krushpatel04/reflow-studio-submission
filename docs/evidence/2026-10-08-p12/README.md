# P12 fit with the renderer's faces (GitHub #33)

What exists: `engine/text_fit.faces(records)`, an opt-in context manager (records `{family, weight, style, path, ttf_sha256}`, ExactManager semantics: bold iff weight>=600/"bold", italic, exact match). Every file is sha256-verified (ValueError on mismatch) before measuring; under it `_path` returns the verified blob path (render.py metric sha == renderer font-event sha). Absent family, missing style or distinct-bytes duplicates = UNMEASURED: RuntimeWarning + uniform geometry, never substitute metrics. Identical-sha duplicates are fine. State is reset on exit/exception. `resize()` and `_path(d, e)` signatures unchanged.

Claims, and only these:
- Default-off: with no context output is byte-identical to main b7548b2 (`hashes_final.txt` == `docs/evidence/2026-10-07-p11/hashes_main.txt`: L1/L2/L3 + P8 run3).
- Official `python -m engine.main` flow is unaffected and still measures with Solstice (`renderer_proof.log`: REAL renderer x3, 0 fallback). The hook only matters once a caller enters `faces()`; the in-tree caller is CLI Engineer's P12b change to `scripts/lica_official/render.py` (separate branch). No quality claim; no real-data claim (lica-official data/font cache not on this host; constructed fontTools faces, advances 500/800).
- Existing tests unedited: `git diff main -- tests_python` = additions only (`test_real_fonts.py`, 0 removed lines).
- Mutants (`mutants.log`, 16): 13 killed, 3 survived: `cache-not-cleared`, `cache-not-cleared-on-exit`, `cache-never-cleared`. Each is EQUIVALENT on its own: the enter and exit `_font.cache_clear()` calls are redundant with each other. Removing both is killed (`cache-never-cleared-both` in `mutants.log`, 2 tests).
- D1 deviation, disclosed: D1 asked for a cache keyed by the verified sha256. This commit instead keeps the path-keyed `lru_cache` on `_font` and clears it on `faces()` enter AND exit (try/finally). Isolation is covered by `test_font_cache_does_not_serve_old_bytes_for_same_path_and_size` and `test_same_path_rewritten_bytes_does_not_leak_across_tasks`. Residual: the cache is path-keyed, so bytes rewritten in place at one path DURING a single `faces()` block are not detected (files are hashed once on enter). A sha-keyed variant exists unpublished; not claimed here.
