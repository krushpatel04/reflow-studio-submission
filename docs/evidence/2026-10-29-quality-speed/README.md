## Problem, test-first change, result

A pre-change bounded local `cProfile` sample on a synthetic 100-text × 1,000-character task counted 572,000 Pillow `getlength` calls, about 6.1 seconds of an eight-second sample. The former `_block` measured every occurrence even when characters repeated within the same font/content. A new counting-font regression in `tests_python/test_text_fit.py` compared wrapping to independently supplied widths and failed **19 calls != 4 distinct characters** on the original code. The two-line change in `engine/text_fit.py` measures each distinct character once per `_block` call; it does not persist metrics across fonts, calls or documents. The test then passed. No new dependency or search/layout policy was added.

Paired, alternating old/new Python measurements, three trials per variant with the same frozen input, gave layout medians **0.096 → 0.020 s** for dense16 and **0.137 → 0.052 s** for public Level 3. Both paired JSON hashes remained equal. These are local layout timings, not complete container latencies or Adobe-machine percentiles. A new local dense100 run finished in **34.396 s**; all 100 synthetic texts still warned that no candidate meets the readability floor. The earlier instrumented/emulated-amd64 baseline timed out at 60 seconds in all six runs; the environments differ, so no numerical end-to-end improvement is inferred from that comparison. The complete pre-change workload profile under ignored `reports/quality-speed-profile-20261029/profile.json` was evidence-complete but **behavioral acceptance false**. Its missing-assets overlay returned silent success without a visible finding, independent of this font fix.
