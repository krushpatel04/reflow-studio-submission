# Finding selection in previews

Problem/evidence: Issue #9 requires a finding to locate its affected element in the relevant preview. Current findings are plain list text: no focusable control and no selection highlight. Stable element IDs already exist in the SVG, so the workbench can connect them without changing layout or diagnostics.

Behavior/scope: A finding with element IDs becomes a native button; keyboard or pointer activation highlights only those elements in that card's preview, with its explanation still visible. Repeated activation clears selection. Other cards and findings stay unselected. Findings without an element ID remain explanatory text, not a misleading control. Preserve selection across overlay redraw for the same design and mode; do not transfer it to a different design or comparison mode.

Risk: Finding IDs can include more than one affected element; select every listed ID, not the whole artwork. UI-generated values must be escaped. Native buttons provide keyboard focus and pressed state; the visual treatment must remain visible in light/dark themes.

Steps/checks: Add a real-browser regression with a large headline, a plain-language finding and a healthy unselected element/card control; confirm it fails because no selection control exists. Add minimal delegated interaction and SVG-element highlight styling; run focused browser acceptance, full browser suite, `npm test`, `npm run build`, `npm run verify`, `npm run benchmark`, and inspect desktop/mobile previews. This does not complete manual accessibility or native Express review.

Execution: Browser regression failed before implementation with `Finding has no keyboard-operable selection control`. Focused browser acceptance passed after the fix, including overlay persistence, deselection and comparison-mode reset. The first full browser run had 25 passes and a Playwright trace-cleanup `ENOENT` because browser runners overlapped; serial rerun passed all 26 tests. Node tests passed 711 with zero skips. An initial build caught two TypeScript test-helper generic errors; corrected both; build and 30-layout verify passed, while the 30-case benchmark retained zero selected errors and eight selected warnings. The additional 390px mobile Playwright test first failed because the initial grid has no `aria-busy` attribute; after correcting that test assumption, keyboard Enter selection/deselection passed. Final full browser suite passed 27 tests; build passed. Keep initial failures visible in this record.
