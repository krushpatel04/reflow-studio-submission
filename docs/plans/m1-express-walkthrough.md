> Scope note, October 5: this is a retained internal/scoped plan. The [current Adobe execution sequence](2026-10-05-adobe-execution.md) and [source audit](../evidence/2026-10-05-adobe-launch/README.md) govern next work; this plan is not proof of official Python entrypoint or genuine renderer compatibility.


## Problem and evidence

The local comparison workbench and provisional engine exist, but `docs/express-workflow.md` has no authenticated host observations. Archived Level 1 examples cover nearby square targets, yet their zero-error diagnostics are not independent visual evidence. The #7 corpus has no untouched outside-creator families.

## Scope and risks

Observe one event poster and one product promotion in Adobe Express before choosing any native add-on operation. Record the host's resize, native editing, grouping, variants, selection, and undo behavior, including correction times and screenshots. In parallel, review a small archived Level 1 reference set and prepare outside-creator intake. Do not infer host behavior from API documentation, change the layout engine, or import test sources before permission and split controls are established.

Sign-in access, paid resize features, and add-on API availability may limit the walkthrough. If blocked, report the exact point and keep unobserved cells unknown. Archived source rendering defects must be distinguished from introduced output defects.

## Sequence

1. Check Git state, repo instructions, and the existing workflow/corpus records.
2. In an authenticated Express session, use permissioned event and product designs. For each, capture source dimensions/layers, resize to square/story/landscape where available, edit one label, try a deliberate format exception, group/select, and undo. Time each manual correction from the first edit to an acceptable result.
3. Fill `docs/express-workflow.md` with observed behavior, feature or account limits, correction counts/times, and evidence references. Leave unsupported or untried operations explicit.
4. Compare archived original, uniform baseline, and selected render for `after-dark`, `long-headline`, `grouped-details`, and `intentional-overlap` at square. Check IDs/copy/styles, visible text, group relationships, legal overlap, strategy, and runtime. Report source defects separately.
5. Prepare a creator request and acceptance checklist for at least four independent candidates. Do not send outreach or expose prospective sealed files without a specific communication decision.
6. Only after host observations, present the smallest native editable probe design and its in-canvas checks. Implement only after the design is agreed.

## Acceptance checks

- Both host designs have observations and measured repairs, or a precise access blocker is recorded without invented results.
- The Level 1 record links reproducible archived inputs/outputs and identifies visual failures despite green diagnostics.
- Creator intake asks for layered source, original render, original size, fonts/assets and rights, with private evaluation/reviewer permission and optional public-use permission separated.
- Documentation links resolve, the diff has no whitespace errors, and no code changes are claimed as tested by prose checks.
