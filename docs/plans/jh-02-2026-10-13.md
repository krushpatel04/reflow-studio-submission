# JH-02 — independent typography and source-fidelity review (slice 1)

Packet: [JH-02](../execution/2026-10-13/jh-02.md). Issue: [#105](https://github.com/kj-squared-labs/reflow-studio/issues/105), parent #3. Branch `jh/jh-02-typography-review` from `0ed00ca`. Owner: JunhoHwoang (Package B). The branch uses the owner's `jh/` prefix rather than `jo/`.

## Problem and evidence

The engine's typography checks are automated and engine-adjacent. RF-01 ([evidence](../evidence/rf-01/README.md)) probes single text elements on the real renderer: clipping, overflow, rotation frames, fractional-size truncation, missing glyphs. RF-02 and RF-03 changed layouts and inspected a few renders. Nobody has independently looked at whole rendered outputs as a reader would, so these questions are open:

- whether legal and small copy is legible;
- whether wrapping reads correctly;
- whether rotated text is placed sensibly;
- whether the supplied brand faces actually render.

Concrete leads from merged evidence:

- RF-02 records grouped labels at **6.67 px** (badge) and **8.15 px** (CTA) and a minimum rendered text size of **6 px** on the Level 2 wide output. Grouped text is unchanged by design.
- RF-01 records that upstream draws at `int(fontSize)` while wrap is measured at the float size. It also records that the Solstice faces have no `kern` feature, and that complex-script text is unshaped. These are known limits. Their visible effect on real outputs has not been reviewed.
- RF-02's Level 2 subhead wraps with a one-word orphan ("hour.").

A matching font hash proves that the right font bytes were loaded. It does not prove that glyphs, lines and sizes render correctly, and this review keeps those two claims separate.

## Scope of this slice

In scope: the three public official samples (`level1_warmup`, `level2_core`, `level3_advanced`) rendered by the current engine and the real upstream renderer on this machine. Each is reviewed at its sample target and at native and presentation scale. The retained RF-02/RF-03 renders are reviewed as already-accepted references. Findings are recorded, never fixed.

Out of scope:

- editing `engine/**`, `scripts/quality/**` or any helper to make a finding pass;
- held-out, validation or sealed inputs;
- the corpus;
- the Package A source-fidelity review (KR-01 has not delivered a bundle yet; it gets its own slice);
- visual-quality scoring.

## Acceptance checks (evidence work, no artificial tests)

1. **Provenance.** Record the source SHA, the upstream SHA `a44a060`, the input JSON SHA-256 per sample, and the output JSON and PNG SHA-256. A second render must reproduce identical PNG hashes, or the difference is reported.
2. **Real rendering.** Each output is confirmed as produced by the real Skia renderer, not the box fallback, using the existing qualification signal. A run that cannot prove this is reported as blocked.
3. **Per text element**, a table with:
   - ID;
   - copy;
   - fitted float size and the integer size actually drawn;
   - the rendered lines;
   - RF-01 probe results (overflow, clipping, notes);
   - supplied face and hash match;
   - a human verdict at native (1×) and presentation (2×) scale.
4. **Each finding** carries the sample, the element ID, the input hash, native and 2× crops, the command that reproduces it, and a severity: *defect*, *risk*, or *known limit*.
5. **Controls.**
   - Negative: RF-01's `clip_failure_real.png` must be judged as clipped under this procedure.
   - Positive: `clip_control_real.png` must be judged clean.
   - If either control misjudges, the procedure is wrong and the review stops.
6. **No production changes.** `git diff --stat main` touches only `docs/evaluation/typography/**`, `docs/plans/jh-02-2026-10-13.md` and `docs/evidence/jh-02/**`. Generated output stays in the git-ignored `reports/jh-02/`.

## Risks

- **macOS versus Linux.** The pinned environment is documented for Linux, and Pillow and Skia defaults differ by platform. If macOS output hashes differ from the pinned Level 1/Level 3 hashes in the tests, the review reports the difference and labels its renders "macOS", rather than presenting them as the submission's output.
- **Readability.** A legibility judgment at 6–8 px is human and subjective. Each verdict names the scale it was judged at, and is labelled a review opinion, not a measured threshold.
- **Contradicting earlier evidence.** Findings may contradict RF-02/RF-03 acceptance. They are reported as findings for the engine owner, not as reversals.

## Steps

1. Set up the pinned upstream (`a44a060`) and a Python 3.11 environment outside the repository. Run the README reproduction to get `output/` for the three samples; record hashes and real-renderer evidence.
2. Run the controls (check 5).
3. Generate per-element data with the existing RF-01 probe, read-only, plus crops at 1× and 2×, into `reports/jh-02/`.
4. Inspect every image; fill in the element tables and findings.
5. Write `docs/evaluation/typography/2026-10-08-official-samples.md` (findings) and `docs/evidence/jh-02/README.md` (provenance, commands, controls, limits). Then request independent review on #105.
