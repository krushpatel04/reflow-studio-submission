## Problem and evidence

Nothing has ever run inside Adobe Express. The September 23 manual session inserted a native title, but the edited text did not survive a reopen ([express-workflow.md](../express-workflow.md)). The September 26 automated session stopped at Adobe sign-in ([host-check.md](../evidence/2026-09-26-issue4/host-check.md)). Every host column in the [SDK matrix](../evidence/2026-09-26-issue4/sdk-support.md) is NOT TESTED. As a result, the team cannot say whether an add-on can create native text, keep its identity, and survive a user edit and a reopen. A native Reflow integration and the possible viewer add-on both depend on that.

## Scope of this slice

In scope: one native text element, created by the add-on, tagged with a source ID, then natively edited by a person, saved, reopened, and moved twice by a repeated operation. Out of scope: images, groups, multiple pages, running the Reflow engine, UI polish, authenticated submission. Express access is the owner's account; no credentials go into the repo, chat or issue.

## Intended behavior

`experimental/addon/` contains:

1. `playground/` — HTML, Iframe JS and Document JS to paste into Playground Add-on Mode. The panel can **Create probe text**, **Snapshot** the tagged nodes on the current page as plain JSON, and **Apply move** with an operation ID. The sandbox returns plain records (`id`, `type`, `text`, `bounds`, `rotation`, `addOnData`), never native proxies.
2. `compare.mjs` — a dependency-free Node comparator. Given labelled snapshots, it reports each transition's changes and checks three invariants:
   - exactly one node per source ID in each snapshot (no duplicates after a retry);
   - a stable native ID for each source ID across all snapshots;
   - the metadata tag is still present (a node whose ID is known but whose tag is gone is reported as metadata lost).

   Whether text or position changed is reported, not judged: the person states which transitions should be unchanged (for example `edited → reopened`) with `--expect-same`.

A host run records snapshots A (created), B (natively edited), C (after save/close/reopen) and D (after applying the same move operation twice), plus host undo observed by hand. Results go to `reports/jh-01/` (ignored); reviewed evidence goes to `docs/evidence/jh-01/README.md`.

## Risks

- The Playground may reject `import` in Iframe JS, or provide `addOnUISdk` differently. That is recorded as an observation and the paste files are adjusted, not hidden.
- Sign-in, Premium or add-on-development gating may block the run. Then the deliverable is the exact blocker with a screenshot, which the packet accepts.
- Metadata is a candidate mapping mechanism, not a transaction system. A missing tag after reopen is a finding, not a probe bug.
- A resolved API promise is not proof of a native edit, a save or an undo; each needs an observed snapshot.

## Steps and acceptance

1. Tests first: `node --test experimental/addon/compare.test.mjs` covers a clean round trip (positive control), a duplicate after retry, a changed native ID, a lost metadata tag, a missing node, a text change reported under `--expect-same`, and invalid input. It must fail before `compare.mjs` exists.
2. Implement `compare.mjs` until green; run `npm test` and `npm run build` to show the existing suites are untouched.
3. Write the paste files and a run sheet (`experimental/addon/README.md`).
4. Host run by the owner in Express (needs sign-in). Record the host, browser, date, the Playground/manifest settings, and snapshots A–D. Run the comparator on them.
5. Write `docs/evidence/jh-01/README.md`: official sources and the viewer conflict, observed IDs/text/bounds before and after, comparator output, undo observation, blockers, and limitations. Then request independent review on #104.
