Preserve face-context isolation, hash validation, font metrics and deterministic eviction. If font work is not dominant, do not implement this. Keep any cache memory bounded; avoid broad refactors or new dependencies.
4. **Improve quality from observed Python failures.** Inspect the dense official banner and the five Python development compositions at native pixels; distinguish lost copy, clipping, unwanted collisions, weak hierarchy and small brand assets. ## Acceptance and limits

- Exact-source, no-skips Python verification passes; affected positive/negative regressions show red-before/green-after for behavior changes. Run repository Node/build/native/benchmark gates only when affected, as required by contributor instructions.
- JSON schema/content invariants hold and rendered PNGs use the real converter; unchanged cases remain byte-identical where feasible. Changed cases receive human review at actual target size. Exposed samples do not imply hidden-set performance.
- Performance claim includes baseline and candidate timings with the same environment/inputs, phase profile and memory; no slowdown outside run-to-run variation on the measured workload, and a clear material reduction in the dominant cost. There is no invented millisecond target or claimed official budget.
- Final release qualification is tied to its exact engine/package bytes. Organizer viewer/access and participant blockers remain separate; engine tuning cannot resolve them.
