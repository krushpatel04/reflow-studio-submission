# RF-03 plan: floor accounting at the rigid group upscale (#97)

Source: accepted main 69464b9 (tree 7f26376b). Owner: Engine Engineer. Engine-only slice.

## Reproduced defect
Public Level 3 sample, real renderer + `scripts/quality/text_ink.py`. Four rows have `font_size == 5.999999999999999`; the renderer draws `int(font_size)` = 5, below `FLOOR_PX = 6.0`:

| target | text | source size | font_size | drawn |
|---|---|---|---|---|
| 728x90 | cta_label | 22 | 5.999999999999999 | 5 |
| 2000x300 | cta_label | 22 | 5.999999999999999 | 5 |
| 1600x400 | ribbon_label (rot -12) | 20 | 5.999999999999999 | 5 |
| 160x600 | ribbon_label (rot -12) | 20 | 5.999999999999999 | 5 |

Cause: `_place_groups` sets `f = FLOOR_PX / font_size` and `_unit` multiplies it back (`fs * (6 / fs)`), landing 1 ulp under 6. `_sub_floor` (strict `<`) still sees the group as sub-floor, but `_raise` filters with `font_size < FLOOR_PX - 1e-9`, so the P10 raise skips it and nothing rounds it up. At 728x90 the ribbon garbling is a separate cause (label exactly 6.0, rotated -12): out of scope.

## Choice: drop the epsilon in `_raise`'s `low=` filter (Reviewer's version)
Not the near-floor snap in `_unit`. Reasons:
- `_raise` is the fit gate: it sets a label to FLOOR_PX only if every sub-floor label of the group fits its own box at 6px (`ceil(widest*1.02)+1 <= width`, lines*6*line_height <= height). A snap in `_unit` would force 6 with no fit check, which can hide an unsatisfied constraint. Dropping the epsilon routes the 1-ulp rows through the existing gate.
- One token deleted; `_sub_floor` is already strict `<` at 69464b9 (no change needed there).
- If a 5.999999999999999 label does not fit, it keeps its value (reported limit, as today for sub-floor groups); nothing is forced.

## Controls (`tests_python/test_extreme_composition.py`, RED first)
1. Every text on the public L3 sample: `int(font_size) >= FLOOR_PX` at 728x90, 2000x300, 1600x400, 160x600 (RED today: the four rows above).
2. Impossible fit: a group label whose box cannot hold 6px text stays sub-floor, unchanged geometry, no silent raise (the unsatisfied constraint stays visible).
3. Epsilon edges, each compared against base `_raise` behaviour (not a literal): only the [6-1e-9, 6) sliver changes. Sliver value + fitting box -> raised to exactly 6.0. Sliver value + too-narrow box -> NOT raised, constraint stays visible, same as base. Outside-epsilon (6-1e-6, 5.9999, 5.5) -> output identical to base (fit gate already raises fitting labels, unfitting stay).
4. Nearby sizes of the 728x90 target (e.g. 730x90, 728x92) stay >= floor.
5. Valid overlap: group plate/label overlap and source-overlapping non-text pairs are preserved.
6. Group / rotation / paint preserved: ids, z_index, group_id, rotation, content, colour, opacity, asset_id, shape/fill, geometry untouched; only `font_size` of the four rows changes.
7. Rotated `ribbon_label` (-12): drawn >= 6 at 160x600 and 1600x400 (no existing test pins it).
8. Rendered small-legal-copy check: `legal_text` renders with ink at drawn 6 (real renderer probe), plus the four rows drawn >= 6.

## Acceptance (not by hash)
Real-renderer before/after (drawn size + ink) for the four rows, `ribbon_label` shown explicitly at 160x600 and 1600x400 (rotated). If `ribbon_label` still draws 5 after the fix, it is reported as an unsatisfied constraint, not hidden.

Pins: the fix flips exactly two pins, `tests_python/test_shape_obstacles.py` `L3_HASH` and `tests_python/test_text_fit.py` `SubFloorLabelRaise.MAIN["C1_l3_120x600"]` (hash re-measured on this tree). Edited in one separate pin commit after the behavioural commit, with old/new hashes and L1/L2-unchanged proof in `docs/evidence/rf-03/README.md`. No other pins.
